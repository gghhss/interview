    事件循环

    # 事件循环

    # 进程：

    程序运行需要有自己的专属内存空间，可以把这块内存空间简单理解为进程；

    # 线程

    有了进程就可以运行代码，运行代码的主体就是线程。一个进程至少有一个线程，跟随进程创建启动的线程称之为主线程；

    # 浏览器进程模型（主要包括浏览器进程、网络进程、渲染进程）

    # 事件循环

    1. 在最开始的时候，渲染主线程进入一个无限循环；

    2. 每一次循环会检查消息队列里是否有任务存在，如果有，就取出第一个任务执行，执行完成后进入下一次循环，如果没有，则进入休眠状态。

    3. 其他所有线程（包括其他进程的线程），可以随时向消息队列里添加任务，新任务会添加到消息队列末尾，在添加任务是如果主线程是休眠状态，则会将其唤醒以继续循环拿取任务。

    # 面试题：如何理解 js 异步？

    • js 是一门单线程语言，这是因为它运行在浏览器的渲染主线程中，而渲染主线程只有一个，且渲染主线程承担着诸多的工作，如渲染页面，执行 js 都在其中运行。如果使用同步的方式，就极有可能导致主线程产生阻塞，从而导致消息队列中的很多其他任务无法得到执行，这样一来，一方面会导致繁忙的主线程白白消耗时间，另一方面导致页面无法及时更新，给用户造成卡死现象。

    • 所以浏览器采用异步的方式来避免。具体做法为当某些任务发生时，比如计时器、网络、事件监听等，主线程交给其他线程去处理，自己立即结束任务的执行，转而执行后续代码，当其他线程完成时，将事先传递的回调函数包装成任务，加入到消息队列末尾排队，等待主线程调度执行。在这种异步模式下浏览器永不阻塞，从而最大限度的保证了但线程的流畅运行。

    # 4、任务有优先级吗？

    1. 任务没有优先级，在消息队列里先进先出。
      但消息队列有优先级。
      随着浏览器复杂度的急剧提升 W3C 不再提宏任务的说法，根据 W3C 最新解释：
    • 每个任务都有一个任务类型，同一种类型的任务必须在一个队列，不同类型的任务可以分属不同的队列，也可以在同一队列。在一次事件循环中浏览器可以根据实际情况从不同队列中取出任务执行；
    • 浏览器必须准备好一个微队列，微队列中的任务优先所有其他任务执行。

    1. 目前 chrome 实现中至少包括以下队列：

      延时队列：用于存放定时器到达后的回调函数，优先级（中）
      交互队列：用于存放用户操作后产生的事件处理任务，优先级（高）
      微队列： 用户存放需要最快执行的任务（最高）

      添加到微队列方式，Promise、MutationObserver； 立即把任务添加到微队列： Premise.resolve.then(fn);

    # 面试题：js 的事件循环

    • 事件循环又叫消息循环，是浏览器渲染主线程的工作方式。

    • 在 Chrome 浏览器源码中，它开启一个不会结束的 for 循环，每次循环从消息队列中取出第一个任务执行，而其他线程只需要在合适的时候把任务添加到任务队列末尾即可。

    • 过去把消息队列简单分为宏任务和微任务，这种说法目前已无法满足复杂的浏览器环境，取而代之的是一种更灵活多变的处理方式。

    • 根据 W3C 官方的解释，每个任务有不同的类型，同类型任务必须在同一队列，不同任务类型可以属于不同的队列。不同队列有不同的优先级，在一次事件循环中，有浏览器自行决定取哪一队列的任务，但浏览器必须有一个微任务队列，微任务队列的任务一定具有最高的优先级，必须优先调度执行。

    # 总结： 单线程是异步产生的原因，事件循环是异步的实现方式。
